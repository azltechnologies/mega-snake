# Changelog

All notable changes to `mega-snake` are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

This file is written by hand, on purpose. It is read by people who install `mgsnake` and want to know what
changed for *them* — not by people reading the commit log. The exhaustive, auto-generated list of commits
lives in the GitHub Release body (`gh release create --generate-notes`); this file is the curated half.

**Releasing:** every release must have its own `## [X.Y.Z]` section here, matching the `version` field in
`pyproject.toml` and the `vX.Y.Z` tag. `.github/workflows/release.yml` refuses to publish otherwise.

## [Unreleased]

### Added

- **`generate-docs` and `man`.** The command reference (`COMMANDS.md`) is now generated by introspecting the
  live Click objects and appending the hand-written fragments in `resources/docs/`, so the synopsis, options,
  defaults and aliases can no longer drift from the code. `man` pages the same reference in the terminal,
  either whole or for a single command, and works on PowerShell where `man` does not exist.
- **`diff-tree --scope`.** Chooses how much of the work to include: committed only (default), committed and
  staged, or also unstaged and untracked. Untracked files are reported as additions, and pending work is
  listed above the commit list.
- **`diff-tree --target`.** Moves the far end of the comparison off `HEAD`, so a past range can be inspected
  by naming both of its commits. Refused for the staged and unstaged scopes, which only exist for `HEAD`.
- **Automated release pipeline.** Publishing to PyPI now runs from a GitHub Release, gated on the tag
  matching `vX.Y.Z`, the version in `pyproject.toml` agreeing with it, and this file documenting the release.
  `twine check` validates the distributions before the upload.
- **This changelog.**

### Changed

- The PyPI long description is now assembled with `hatch-fancy-pypi-readme` instead of shipping `README.md`
  verbatim.
- `ws_advice` writes to stderr, keeping the stdout of `no_init` commands clean for shell substitution
  (`. "$(mgsnake shell-path bash)"`).

### Fixed

- **Duplicate command and alias registrations are now rejected.** Click's registry silently replaced an
  existing command when a second one claimed its name, leaving the first unreachable while its tests kept
  passing. Registration now fails loudly, naming both colliding modules.

## [0.1.5] - 2026-07-26

### Added

- `--version` / `-v` on the root command.
- `scan-dependencies` became a multi-ecosystem audit engine: the ecosystem is auto-detected from the
  lockfiles (Python/uv, Java/Gradle/Maven, Node) with a generic OSV-Scanner fallback, and `--ecosystem`
  forces it.

### Fixed

- `diff-tree` crashed with a `UnicodeDecodeError` when a binary file appeared in the diff. Binary files are
  now detected and written with a placeholder instead of their raw bytes.
- `osv-scanner` failures are reported instead of being swallowed.

## [0.1.4] - 2026-07-24

### Added

- **`scan-dependencies` (`sdep`, `audit`).** Scans the project's locked dependencies against the OSV advisory
  database and files one GitHub issue per new finding — package, installed version, recommended version and
  advisory link — skipping findings that were already reported. `--dry-run` prints them instead. The issue
  labels are created if they do not exist yet.
- Dependabot configuration and a scheduled dependency-scan workflow.

### Fixed

- `gh issue list` and `pip-audit` no longer have stderr merged into their JSON output, which corrupted
  parsing whenever either tool printed a warning.

## [0.1.3] - 2026-06-08

### Changed

- Capped the supported Python range at `>=3.12,<3.14`. It was previously unbounded (`<4.0`), which advertised
  support for interpreter versions the project had never been tested against.

## [0.1.2] - 2026-06-08

### Changed

- Version bump only, to correct the metadata of the published package. No functional change.

## [0.1.1] - 2026-06-08

The release that turned a folder of shell scripts into an installable Python package.

### Added

- **Installable distribution.** The tool is now a `uv`/`hatchling` package (`uv tool install mega-snake`)
  instead of scripts sourced from a clone, with `mgsnake shell-path` bootstrapping the shell integration.
- **Maven support**: `set-maven` and `maven-project-setup`, aligned with the existing Gradle flow.
- **Command aliases** across the whole CLI, and a local developer config file (`init-local-config`) that is
  ignored by git.

### Changed

- Commands moved to kebab-case (`set-java`, `remote-branches-cleanup`), with the previous names kept as
  aliases.
- The package was renamed from `codename_snake` to `mega_snake`, and the source moved from `py/` to
  `src/mega_snake/`.
- Tooling migrated to `uv` and `ruff`.

### Removed

- The `gcloud` module was deferred out of the distribution to `offproject/`; it is not part of the published
  package.

## [0.1.0] - 2026-06-08

First publication to PyPI, of the tool as it existed before the packaging work in `0.1.1`. It is
recorded here for completeness: everything below was replaced one release later, so `0.1.0` is only
useful as the description of where the project started.

At this point `mgsnake` was a repository you cloned, not a package you installed:

- **Installation was `source`, not `install`.** `config_setup.sh` / `config_setup.ps1` were sourced
  from the clone, exported `WS_CONFIG_HOME` pointing back at it, and activated a virtual environment
  declared in `config.properties`. There was no `mgsnake` executable — the shell functions invoked
  `python3 -m <module>` directly, with `PYTHONPATH` set to the checkout.
- **Half the tool was shell.** `src/` held the commands as standalone scripts (`javaSet.sh`,
  `gradleSet.sh`, `expiredCertsJks.sh`, `gcloudSet.sh`, `parseJsonLogs.sh`, `formatting.sh`), while
  the Python half lived in `py/` under the `codename_snake` name, with its own nested
  `py/pyproject.toml`.
- **The command set was already recognisable**: environment configuration, `diff_tree`,
  `create_release`, `remote_branches` and `branch_cleanup` — under snake_case names, without aliases.
- Linting was `pylint` (`pylintrc`), and `combine.sh` concatenated the sources into a single file for
  pasting into an LLM.

Everything in this list is gone: `0.1.1` replaced the sourced-clone model with an installable
distribution, moved the shell commands into Python under `src/mega_snake/`, and renamed the package.
